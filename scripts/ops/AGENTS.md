# scripts/ops/ —— 运维脚本执行门禁

本目录存放高风险一次性运维脚本（重写 git 历史、force push 等，多数不可逆）。

## 执行门禁（硬约束）

- **默认禁止执行**本目录下任何脚本——无论任务多相关、推理多合理，都不执行。
- 仅当用户**显式指示**执行时才允许。"显式指示"= 含明确执行动词的直接指令（"执行 X"、"跑 X"、"运行 X"）。
- 以下**都不算**授权，不得据此执行：
  - 用户提及、引用、讨论、让你审计或修改脚本
  - 你自己判断"现在适合执行"或"前置条件已满足"
  - 脚本已通过审计、已就绪
- 拿不准是否算"显式指示"时，**不执行**，先向用户确认。

## 开发例外

编写、修改或验证本目录脚本本身时，可执行脚本中**不改变仓库状态**的部分用于验证：

- ✅ 允许：shellcheck、只读检查（status / list / ls-tree / rev-list 生成）、守卫逻辑 dry-run、临时仓库实验
- ❌ 仍需显式授权：`filter-repo` 重写、`force push`、`worktree remove --force`、运行完整脚本的主流程

## 测试

- 运维脚本测试 co-located（`test_<被测>.sh`），用 `bash test_<被测>.sh` 跑——纯 bash，无外部测试框架（bats/pytest）。
- 测试前置检查 git / git-filter-repo，缺失提示安装并退出。
- 设计：被测脚本主流程包在 `main()` + `BASH_SOURCE` 守卫内，`source` 只暴露函数；测试 source 后调单函数 + 临时仓库集成。
- 集成测试用本地 bare 仓库模拟远端（不碰真网络），等价覆盖 push 路径；真代理探测不可单元测，注释说明。
- shellcheck 全量 gate（主脚本 + 测试）。
