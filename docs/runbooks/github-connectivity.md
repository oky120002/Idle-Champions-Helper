# GitHub 连接异常

## 判断顺序

1. 读取本次操作实际使用的 remote、upstream 或 push URL，确认目标主机。
2. 先执行有界的直连探测，记录超时或连接错误。
3. 区分认证失败、权限不足、DNS/TLS/网络失败和远端服务异常。
4. 仅在连接失败或不稳定时使用仓库环境允许的临时代理兜底；不得改写远端或替换 Git 服务。

`gh auth status` 或 `gh api` 成功不能证明 Git HTTPS/SSH 传输链路也正常。通过 API 修改远端 ref 后，应重新 fetch 并核对本地、远端和 upstream 状态。

代理、令牌和完整 URL 不写入文档或命令输出；故障记录只保留安全的错误类型与目标主机。
