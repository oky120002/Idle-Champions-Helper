# planner 阵型通关可行性模型

**优先级**：待评

## 背景

当前 planner 有三个优化目标：DPS、金币、速度，每次选一个最大化。但在特殊变体中（如「舞会之花拜尔」），通关需要多种能力同时达标：

- 中间格英雄打出足够伤害（DPS）
- 多段攻击清除 boss 护甲（碎甲）
- 全队扛住 boss 周期性 AoE（生存）
- 辅助英雄给中间格叠增伤 + 给全队叠生存层

现有「选一个目标最大化」的模式无法表达「缺一块就过不了」的多维需求。

## 是什么

### 子项一：护甲感知的 DPS 计算

**问题**：当前 DPS 算法假设伤害 = 攻击力 × 增伤系数。但护甲敌人有分段血条，每次命中最多碎一格，溢出伤害浪费。DPS 算法在护甲场景下结果不准。

**方向**：不新增并列维度，而是让 DPS 计算在检测到护甲敌人时自动切换为两阶段模型（先碎甲、再杀人）。护甲机制详见 `docs/research/gameplay/armored-enemies.md`。

**待确认**：单发伤害低于护甲阈值时是完全无效还是累积扣减——决定低系数多段英雄（如法莉德 0.33 系数）的实际碎甲效率。需游戏内实测。

### 子项二：生存维度（门槛约束）

**问题**：阵型被 AoE 灭团时实际 DPS 归零，但 planner 不会反映这一点。

**方向**：新增「生存」维度，跟 DPS / 金币 / 速度并列计算和展示。但在优化时作为**门槛约束**使用——扛不住的阵型直接淘汰，超出门槛的部分不加分。不是「越肉越好」。

**UI 口径**：每个目标需在 UI 上标明行为模式（DPS/金币/速度 = 越高越好；生存 = 够用就行），避免用户误解。

**生存机制分类**（详见 `docs/research/gameplay/aoe-survival.md`）：
- 完全免疫（巴尔德里克黑暗交易、梅亨首击免疫、贝洛斯复活、斯特丽克丝替死）
- 全队减伤（克莱达 75%、赛丽斯同列减伤）
- 临时生命值/护盾（沙卡全队、伊梦石肤术）
- 持续治疗（巴尔德里克、维康妮亚等）

### 子项三：通关可行性判定（多维约束组合）

**问题**：不同变体激活不同的通关条件，有些维度可以「空」（不检查），有些需要达标。

**方向**：抽象出「通关条件检查」层，每个变体按需激活检查项：

```
通关判定 = 生存门槛(可空) AND 碎甲门槛(可空) AND DPS 排序
```

- 先过滤：不满足生存/碎甲门槛的阵型直接淘汰
- 再排序：在存活的阵型里选 DPS 最高的

**搜索行为**：不需要手动指定「带个治疗」「带个多段英雄」。搜索算法尝试各种英雄组合，靠门槛约束自动淘汰缺角色的组合，最终找到同时满足所有条件的阵型。

### 子项四：变体机制感知

**问题**：变体有图内规则（如「只有中间格能打伤害」），改变 DPS 怎么算和通关需要什么。

**方向**：变体规则需映射为 planner 可消费的结构化约束。部分已有（赞助人资格、白名单、座位锁定），缺失的是图内机制对 DPS 计算和通关条件的影响。

**已知图内机制类型**：
- 伤害限制（只有特定位置/英雄造成伤害）
- 特殊敌人（护甲 boss、hits-based 敌人、AoE boss）
- 阵型限制（占用座位、相邻要求）

## 为何暂缓

子项一（护甲 DPS）和子项二（生存维度）各自是中等复杂度的建模任务，但子项三（通关判定）需要改变 planner 的搜索/排序架构——从「单目标最大化」变为「多约束过滤 + 单目标排序」。子项四（变体感知）需要将非结构化的变体描述文本映射为结构化约束，工程量和语义判断都很大。

护甲击破机制本身还有待实测确认的细节（低伤害命中是否累积）。这些不确定性使整体方案需要分阶段推进。
