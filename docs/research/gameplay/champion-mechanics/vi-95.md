# 蔚（hero_id=95）机制实测

- 数据快照日期：2026-07-27（area=193，7 名善良/中立英雄阵型）
- 关联参照：`src/domain/planner/references/vi95ReferenceData.ts`
- 数据缺口：阵型完整 heroId 未提供（参照 `scenario.formationHeroIds` mock 为 geneutral carry + 5 个善良占位 + 蔚 support，用户补实测后替换）

## 角色定位（勘误）

**蔚是 support（提供善良榜样给出言不逊增强），不是自己的 carry。** 善良榜样 `filter_targets: geneutral`，`geneutral` 是伦理中立阵营标签（Neutral / Lawful Neutral / Chaotic Neutral）。蔚自身 `Neutral Good`（伦理 good）**无 geneutral 标签**（raw `hero.original.tags` 确认），不可能是自己善良榜样的目标。carry 须另选 geneutral 英雄（如 Jaheira、Deekin、Nrakk 等 47 个 geneutral 英雄之一）。

游戏内善良榜样「叠层系数」显示的是**能力对 geneutral 目标的输出倍率**，非蔚自身 DPS。早期调研误把蔚当 carry 吃自身善良榜样，是概念错误——已修正参照数据与测试。

## 原话（用户描述）

- 「善良榜样」：阵型中每有一名善良/艾奎兹玄/C小队勇士，伦理中立勇士（geneutral）伤害 +300%，乘算堆叠（当前 7 层）。
- 「出言不逊永不够」：每层「出言不逊」使善良榜样 +0.33%（乘算），层数上限=最高区域×10（当前 1930）。

## 机制分析

蔚同时用 4 个通用机制（非蔚专属）：

- `formation-count-mult-stack`：善良榜样 per_hero mult，count=good|acqinc|cteam，target=geneutral。
- `dynamic-stack-multiply`：出言不逊 stacksMultiply，层数来自 `highest_available_area×10`（数值表达式，归一化降 unsupported，由 `manualStackCount=1930` 提供假设）。
- `bonus-scale-linkage`：出言不逊挂在善良榜样上（`bonusScaleOfSignal` 依赖检查，不卷入数值）。
- `buff-upgrade-modifier`：道德规范（specialization +20%）/ 时髦披肩（equipment +157.8%）修饰善良榜样。

count 限定 vs target 限定：蔚 ed=1644 同时携带 `stack_func_data:{tag:"good|acqinc|cteam"}`（count）与 `filter_targets:[{by_tags:geneutral}]`（target），二者语义不同，归一化须分别读入 `formationCountQualifier` 与 `targetQualifier`，不可混用。

`geneutral` 标签语义：伦理中立阵营（Neutral / Lawful Neutral / Chaotic Neutral），全库 47 个英雄有此标签、且全是伦理中立；`Neutral Good` 英雄（含蔚）均无此标签。

## 推导与偏差

- 善良榜样：`4^7 = 16384`（7 名 good 英雄，per_hero 计数；对 geneutral 目标生效）。
- 出言不逊：`1.0033^1930 ≈ 577`（0.33%/层 是游戏取整显示，实际略低；游戏叠层加成 57,639% = 576.39 倍，吻合）。
- pool 倍率（**研究 flat-factor 分解**，非代码产出）：`16384 × 577 × 1.2 × 2.578 ≈ 2.92e7`，对照游戏善良榜样「叠层系数」`2.92e09%` = 2.92e7 倍，偏差 < 1%。此分解把修饰作独立乘 ×(1+修饰/100)，是研究对游戏机制的解读；代码实际 pool 组合见下条。
- 不对照绝对 DPS：`baseDamage` 未校准，绝对 DPS 须 BUD 校准联动（绝对值校准属后续工作）。
- buff_upgrade 修饰折算（**代码实际**）：外部源 buff_upgrade（loot 装备 / feat / 专长，非 stacksMultiply）按基础 `value`（per-stack 百分比，善良榜样=300）× 修饰值/100 折算进 addPercent，**非**聚合倍率（4^N）——用聚合倍率会使 +100% 修饰被算成 ×4^N（灾难高估，已修）。ability 源静态 buff_upgrade（ranked 进阶 + 同 ability 源 effect_keys 静态修饰，如劝人向善 +200%）的贡袋已烘进 effect_string snapshot value，不再派生（见修复记录 #3）。
- pool 对照现状：修复 progression 双重计数后，蔚 damage:hero poolMultiplier ≈ 1.66e7（multFactor 16384×576=9.44e6 + 时髦披肩 rarity1 addPercent 75），对照游戏叠层系数 2.92e7 为 0.57×（欠估 1.75×）。欠估来源：(a) 道德规范专长 +20% 未建模（specialization 信号未入 built）；(b) 时髦披肩取 rarity1 +25% 而非最高 rarity +157.8%（loot rarity 选择 bug，见 TODO）；(c) pool addPercent 线性累加 vs 游戏修饰独立乘的近似差。逐项 `multiplierChecks`（per-signal，16384/576）仍是有效自动化校准；pool 级对照待 (a)(b) 补全后落地。

## 评分链路修复记录（2026-07-28 审计）

深度审计发现并修复两处蔚善良榜样评分链路缺陷（此前被手搓测试信号掩盖）：

1. **geneutral 目标门控**：手搓测试信号给蔚塞 `geneutral` 标签（蔚实际没有），使「蔚作 carry 吃自身善良榜样」的虚构场景通过。真实数据端到端测试暴露：蔚非 geneutral → 善良榜样对蔚不生效。修正：参照测试改用 geneutral mock carry + 蔚 support。
2. **heroDpsMultiplier 阵型 buff 定位**（核心评分 bug）：`attachSignalSemantics` 对 `targets:['all']` 的 relation='any' 设 positionQualifier=null，而 `resolvePositionRelation` 对 null 走类型默认（heroDpsMultiplier→'self'），导致所有 `targets:all` 的 hero_dps 信号被当自增益——support 位（如蔚）提供的阵型 buff 永不对 carry 生效。修正：`targets:['all']` 显式设 `{relation:'any'}`，使 support 位跨槽位 buff 匹配 targetQualifier 的 carry（全库 9341 个 positionQualifier=null 的 heroDpsMultiplier 信号中 targets:all 者受益）。
3. **buff_upgrade progression 双重计数**（系统级 22× 高估，影响 162/164 英雄）：`collectEffectEntries` 旧假设「真升级（required_level<9999）全部叠加」，把 ability 源（upgrade effectReference + effect_keys）的静态 plain buff_upgrade 每条派生为独立 +base.value×X/100 addPercent。但 IC 的 effect_def effect_string 是满级 snapshot 计算值，已含该 ability 自身 upgrade 树的全部静态 buff_upgrade 贡献（ranked 进阶 + 同源 effect_keys 静态修饰，如蔚 20 条 buff_upgrade,100,12312 + 劝人向善 buff_upgrade,200,12312）。证据：蔚善良榜样 effect_string=300，游戏显示 per-stack 恰好 +300%（4^7=16384），叠层系数 2.92e7=4^7×576×1.2×2.578 只含 2 个外部修饰器——若 20 条 ranked + 劝人向贤独立叠加，pool 应 6.4e8（22× 高估）。修正：`collectEffectEntries` 派生循环跳过 `ability 源 + plain kind + 非 stacks_multiply` 的 buff_upgrade（归一化期排除，非评分机制；详见 `dps-mechanics.md`「ability 源静态 buff_upgrade 排除」）；保留 stacks_multiply 动态（出言不逊）、复杂 wrapper（per_tagged/distance 阵型依赖）、外部源 loot/feat/legendary（装备/专长运行时修饰）。修复后蔚 pool 1.66e7（0.57× 游戏，欠估来自未建模的专长/装备修饰）。
