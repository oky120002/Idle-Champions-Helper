# 方案存档：范围与数据模型

- 目标：回答“这个模块为什么存在”“当前保存什么”“方案对象长什么样”。

## 模块定位

- 方案存档模块是产品闭环里的“沉淀层”。
- 前面的页面解决“查什么英雄、看什么限制、怎么摆阵型”；这一页解决“当前这套阵容要不要留下、下次能不能快速找回来、这套方案是为哪种目标准备的”。
- 它本质上是个人工作台的本地记录层，不是展示页占位。

## 范围

| 可保存对象 | 结论 | 原因 |
| --- | --- | --- |
| 阵型方案 | 当前支持 | 与阵型编辑页衔接，保存已命名阵容、场景信息与筛选条件快照 |
| 常用筛选组合 | 当前支持 | 独立于阵型方案保存，复用 11 维英雄筛选条件 |
| 阶段性目标清单 | 不属于本模块 | 方案存档不是任务管理器 |

额外约束：阵型页负责"最近草稿"，方案存档页负责"已命名方案"；未命名草稿不进入方案列表。阵型方案携带保存时的英雄筛选条件快照（`filterSnapshot`），英雄列表页可带着当前筛选跳转阵型页，恢复方案时候选池按快照还原。

英雄列表页的常用筛选组合使用独立的 `championFilterPresets` 本地仓库，保存名称、11 维 `CommonFilterSearchState` 和时间戳；不包含 `showAllResults` 等页面展示状态，也不与阵型方案对象混合。

## 数据模型

| 字段 | 说明 |
| --- | --- |
| `id` | 本地唯一标识 |
| `schemaVersion` | 方案结构版本 |
| `dataVersion` | 保存时对应的公共数据版本 |
| `name` | 方案名 |
| `description` | 备注或用途说明 |
| `layoutId` | 对应阵型布局 |
| `placements` | 槽位到英雄的映射 |
| `scenarioRef.kind` | `campaign` / `adventure` / `variant` / `trial` / `timeGate` |
| `scenarioRef` | 正式场景身份；手工联调方案可为 `null` |
| `scenarioTags` | 用户可读标签，不作为恢复主键 |
| `priority` | `low / medium / high`，仅作为个人排序辅助 |
| `filterSnapshot` | 保存时的英雄筛选条件快照（11 维 `ChampionFilterSnapshot`）；无筛选或旧方案为 `null`，恢复方案时按此还原阵型页候选池 |
| `createdAt / updatedAt` | 创建与最近编辑时间 |

卡片里如果需要 `seat` 摘要，应在读取方案时由 `placements + champions` 运行时推导，而不是把它作为长期持久化源字段。
